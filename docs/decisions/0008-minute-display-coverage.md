# 0008：分钟展示覆盖与时间映射缺陷修复

2026-10-16，版本4.1.1。用户要求检查分钟级买卖点过少；按照专项Review区分已确认缺陷与待讨论规则。

## 已确认缺陷及选择

旧`map_time`将任意观察时刻映射到同日第一根不早于它的K线，未验证周期覆盖。通富1m本地数据从9月29日13:42开始，9月29日10:30确认的B3会被挪到13:42，这是时间显示错误。修复后1m/5m/30m/60m要求`0 <= candle.time - point.time < period`，缺少覆盖K线则返回None，明细保留原时刻。周期边界点属于以该时刻结束的上一根K线，不能移到下一周期。日/周/月与4h聚合不变。

同步R03及0003说明；R01/R02的种子、父走势完成、层数和来源约束均不改变。没有放宽背驰、改成笔/线段确认或补造点。前端明确展示周期与计算基础分离，提示本地展示数据最后时间、无K线窗口及按确认时间无法绘制的点数。

## 真实对照及不改规则的原因

旧本地5m截至9月30日：通富笔级7确认+L0一个卖点；立讯笔级18确认/1候选+L0两个卖点。立讯分钟展示数据停在8月，因此9月点无法绘制。仅切换展示为1m不会将计算基础从5m改成1m。

10月16日从原有腾讯1m、新浪5m接口只读抓取，返回至11:30；1m每股320根，5m每股744根。5m与本地同源重叠历史在内存合并至1320根（早至9月1日），参数不变：通富16个笔级确认点、L0一个点；立讯26个笔级确认点、L0五个点。1m单独连续320根：通富36笔/4线段/1笔级点/零递归点；立讯32笔/8线段/3笔级点/L0一个点。没有把断档1m跨月拼接用于该实验。

实时抓取是检查用的独立证据，不自动替换本地数据；分析CSV按新版本对已有完整历史重算。抓取数据及统计保存于`docs/research/minute-coverage-20261016-live-*.json`。一、二类点过滤、盘整背驰是否转为观察点及独立二类点覆盖属于待讨论，不在本次修复中改变。

## 回归约束

新增分钟周期覆盖及真实时间错位复现；手工黄金几何预期保持不变，仅将版本标签更新为4.1.1。旧输入与参数下，笔/段/中枢/点的原始几何及确认时间不应改变，允许复合快照displayTime/displayEndpointTime因修复而变为空。
