# 决策 0001：规则方案与可追溯回归基线

日期：2026-09-30。状态：已实现。授权：用户明确要求按助手理解完善项目、明确缠论原则并防止持续修改退化。本次选择不等于确认了所有未来缠论建议。

## 问题

原有 minKlineGap 默认1，缺少对分型元素共用的命名区分；CSV不记录规则参数或批次。局部日期重算覆盖全量结果，同步又恢复默认间隔。极值候选延伸会使前后笔断开。线段在早期缺口候选未确认时越过该候选确认更晚终点，未来二次确认后可能回写历史。

## 理论与解释

采用双严格分型、方向包含合并、顶底交替、严格成笔价格范围、特征序列线段和已确认线段重叠中枢；详细编号K01至D01见 chan-rules.md。第62课公开转载正文支持分型和方向包含处理，并讨论成笔中的独立K线。独立方案将其解释为三元素不共用且中间留一根，中心差至少4。

现有中枢的构成单元是线段，而原理论以完成的次级别走势类型为基础；DD/GG的统计集合也有差别。因此明确标注工程近似，不从该中枢直接派生买卖点或级别扩张。

## 选择与兼容

- v2.0.0：保留 `legacy` 默认1和原价格范围；新增 `separated` 生效间隔=max(输入,4)，作为推荐的研究对照方案，不命名为完整老笔/新笔。
- 固定规则放入版本化目录，不开放任意布尔组合，避免产生无法解释的混合流派。当前只开放已实现且经过测试的两个方案和1至20整数间隔。
- 修复端点延伸与缺口等待：这是连贯性和确认状态缺陷，不是添加胜率承诺。
- 重算完整本地历史，范围只裁剪展示；同步沿用保存的设置；未知方案或拼写错误拒绝。
- 当前快照单文件原子发布，历史批次保留完整输入、输出及规则目录。CSV是可读导出。哈希用于内容一致性与失效检测，不是防恶意篡改的数字签名。
- 代码/规则/输入改变自动按原方案重建，旧CSV无溯源时按兼容默认值重建，不能复原未知旧设置。

## 影响

旧兼容方案仍可选，但两项算法缺陷修复可能改变原先错误的端点或过早确认的线段。切换独立方案通常减少短笔，从而影响线段与中枢；必须使用相同输入比较，不应把两个不同输入批次的差异全部归因于参数。

历史归档会增长；尚无自动清理，需用户自行备份重要批次。单进程锁不解决多worker写入，维持单worker本地运行。

## 验证要求

- 手工固定的三分型输入与两方案预期，测试不能自动更新基线。
- 极值延伸保持连接、非法范围拒绝、包含高低来源、同价先到、非整数参数拒绝。
- 固定随机种子逐条追加：确认笔与段的几何终点保持前缀稳定，末笔和候选可以变化。
- 日期裁剪不覆盖全历史，同步保留参数，输入/代码/规则改变触发新批次，周期隔离，日内时间保留。
- 模拟导出写盘失败不发布混合结果，并发调用串行发布，损坏快照明确报错。
- 后端完整pytest、前端构建、页面验证和规则变更检查，结果记录在本次变更交付中。
