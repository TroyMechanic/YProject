# 持续修改与防退化

不能证明项目永远没有错误。这里建立的是可执行的检查、可复核的批次和显式决策流程，让行为改变被发现、解释和恢复。

## 修改顺序

1. 复现问题：使用完整归档或固定输入，记录股票、周期、规则版本/方案/间隔、批次和指纹。
2. 分清类别：代码没有遵守已定义原则属于缺陷；改变原则属于新口径。新口径必须有来源和可执行边界，说明为什么选择及影响，不能只写“更符合缠论”。
3. 新增/修改 `docs/decisions/` 决策记录，更新 `docs/chan-rules.md`。改变算法、schema、存储和结果语义时升级 `rule_policy.py` 的 RULE_VERSION；初次新增方案升次版本，默认/历史行为不兼容升主版本，缺陷修复升补丁版本。
4. 添加能复现问题的样本测试；保留相同输入的旧批次。只有明确接受几何差异后才更新固定样本预期，并在决策中写清原因。
5. 用户可见行为更新 `docs/features.md`。TODO仍只记录用户明确计划的工作，不能用本流程自动扩张需求。
6. 跑后端测试、前端构建和变更检查；交互变化验证浏览器。用两个完整快照比较影响，然后交付差异和限制。

## 本地检查

```bash
(cd backend && PYTHONPATH=. .venv/bin/python -m pytest)
(cd frontend && npm run build)
(cd frontend && npm test)
python3 scripts/check_rule_change.py HEAD
```

与目标分支比较时把HEAD换成目标提交/分支，例如 `origin/main`。脚本检查受保护的算法、schema、CSV和服务及图表解释文件：必须同步规则文档、决策记录和规则版本。对这些文件的纯重构也采用保守版本升级，因为代码指纹会变化。测试本身不能证明理论正确，尤其随机样本不能替代人工图形核验。

GitHub workflow用PR基线或push前的提交执行相同检查，后端用Python3.11、前端用Node22与npm ci。依赖固定到当前lockfile中的直接版本，避免latest自动漂移。依赖升级单独提交并验证。

CI文件只有推送后才会在GitHub执行。本地新增它不等于已经开启分支保护；仓库管理员需把 `verify` 检查设为合并必需，才能阻止绕过检查合并。仍不能阻止用户直接修改本地文件。

## 快照与比较

完整存档：

```text
backend/app/data/analyzed/runs/{SYMBOL}_{PERIOD}/{runId}.json
```

每次快照包含全部本地K线、基础结构与全部研究指标和当时规则目录。数据指纹相同才适合比较纯规则/算法差异；不同数据也能比较，但不能解释为单一规则效果。

```bash
python3 scripts/compare_analysis.py /path/to/before.json /path/to/after.json
```

脚本验证全量结果与输入校验值，输出同股票同周期的输入/代码是否一致、旧新参数和各结构新增/移除明细。它忽略单独的reasons文字变化，几何、来源和状态变化仍计入。前端导出的裁剪视图格式不同，不能直接交给完整快照比较脚本。

如需恢复旧结果：先备份当前原行情与分析目录，把完整历史快照复制为当前 `{SYMBOL}_{PERIOD}_analysis.json`，并恢复对应原行情、代码和规则版本。否则下一次查询会按当前代码和原行情重建；不要只恢复四个CSV并期待API采用它们。

快照是本地可复核记录，不是防篡改签名或永久备份。归档没有自动清理。当前锁仅在同一进程有效，使用单uvicorn worker；多worker/多机器部署必须另行建立数据库事务或跨进程锁，不能直接扩大现有部署。

## 回归覆盖

- 固定手工样本：两方案输出、版本显式审查。
- 边界：包含来源、同价分型、严格范围、方案最小间隔、非法输入。
- 历史追加：固定seed的笔/段确认前缀稳定与端点连续性。
- 服务/持久化：日期窗口、参数继承、空同步、指纹失效、批次校验、归档、写盘失败与同进程并发。
- API：请求验证与完整历史重算行为。
- 前端：构建、方案选择、待应用/实际参数分离、原则溯源与图层交互。

图形尚无自动像素基线，行情源复权/实时字段口径尚未统一，严格缠论的全部走势分解、级别扩张及胜率回测尚未实现；已有工程递归口径见规则30/31。这些边界不能由“测试通过”推导为已解决。

研究信号回归覆盖MACD手算、零轴/预热、严格边界、真实趋势一/二类链、三类回试、关闭时间及未来追加确认点稳定性。新研究算法和前端解释映射纳入变更守卫。旧v2快照按原始JSON校验，避免新schema默认字段导致旧校验失效，保留原参数迁移。

递归快照另存 `{symbol}_{display}_hierarchy.json`，包含完整基础输入及父子/确认引用。inputHash为展示输入，基础哈希在hierarchy.baseAnalysis；恢复时也要保留基础CSV及其规则设置。改父走势完成条件必须更新0003及规则R01/R02/R03，用前缀追加验证确认结构与时间。层数不足不能补造节点，点数增加不是验收标准。


## 区间下钻交互回归

`scripts/verify_range_navigation.cjs`在独立无头Chrome中测试本地5173/8000服务，需Node可解析Playwright，并可通过`CHROME_PATH`指定Chrome路径（默认macOS安装路径）。输出到临时目录，可用`YPROJECT_TEST_OUTPUT`指定目录。此脚本验证真实画布数据、日期路径、点击、返回、缺失及错误处理，不操纵用户浏览器。

脚本依赖当前本地002475日/4h/60m真实行情在2026年8月有交集，2023年分钟行情为空；这些是显式回归前提，不是运行时业务假设。行情覆盖改变时应更新测试选区和缺口预期，不补造价格。它是需要真实本地数据的交互检查，不替代CI固定样本测试。通用区间边界测试包含在`npm test`中。


滚轮回归：`scripts/verify_wheel_navigation.cjs`沿用上面的Playwright/Chrome和本地服务条件。它调用真实浏览器wheel事件，核验实际series数据及时间锚点；要求立讯精密2026年8月19—28日的日/60m/30m/1m数据、9月起的5m数据，以及月K数据在本地。测试503故障只替换错误响应，不替换行情。输出包含切换、返回、关闭开关、无数据/错误保持原图、请求去重及最细/最粗边界。


顶部周期按钮回归：`scripts/verify_period_buttons.cjs`使用相同运行条件，验证8种按钮、自动密度、当前时间居中、重复点击恢复缩放、首个滚轮不立即跳档、缺锚点提示、失败保留原图、开关状态保留和窄窗口。使用立讯精密本地2026年8月至10月历史；有意用5m缺失8月的事实验证显式定位提示，不伪造价格。
