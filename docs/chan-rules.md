# 缠论规则说明

4.3.1 周期按钮缩放联动（决策0012）：顶部周期按钮显式切换时加载目标周期完整本地历史，以当前画面中间的真实K线为时间锚重新适配显示密度；清除上一周期的下钻路径、滚轮缩放与失败锁定状态。同位置缺行情时明确提示并定位目标周期最新本地行情；整个周期无行情或请求失败则保留原图。与滚轮无锚点时保留原图的策略分开。仅改变展示导航，缠论结构、参数、行情及买卖点规则不变。

4.3.0 滚轮多周期导航（决策0011）：放大/缩小可在展示周期间自动切换，A股自动阶梯为月/周/日/60m/30m/5m/1m，手动4h仍保留。只改变查看周期与视窗，R01/R02/R03及全部计算规则不变。滚轮以鼠标所指K线时间为锚，分钟视窗保留日内边界；目标无锚点覆盖或请求失败时保留原图并在图旁提示。不得回退到其他历史日期或模拟行情。

4.2.0 区间下钻（决策0010）：从展示图选定起止交易日期，再查询更细周期的同一区间；日期只裁剪展示，不从截断历史重新构造结构。下钻显式继承当前递归基础周期和最大层数，K线周期切换不代表结构层级的父子认定（R01/R02/R03保持原口径）。返回恢复父图查询和可见日期范围。日内选区包含两端整日，周/月选区包含端点K线的完整日历周/月；不伪造缺失行情。显式区间优先于日K默认基础行情聚焦。本次不改变算法、指标、结构和买卖点几何。

4.1.2展示修复（决策0009）：主图与MACD共用K线/指标/已开启结构端点的有序时间集合，缺少实值的时刻只保留whitespace。二者按同一逻辑索引同步，默认视窗按真实展示K线定位，不能被窗口外旧端点拉长。日K仍聚焦基础行情覆盖范围。此规则只影响绘图，不改变原始K线、MACD值、结构或买卖点。

展示状态补充：切换展示周期会更新K线及对应MACD，不改变R02计算基础。图旁标题显示实际已加载周期，加载期间的旧图不表示新周期结果；买卖点文字中的周期继续表示计算来源。本次仅为页面状态提示，不修改规则、快照或图表计算。

4.1.1修复分钟展示时间映射，见决策0008：不改变点的成立条件、原始端点及确认时间。展示周期切换不改变计算基础；本地行情时间与当前日期必须分开核验。

## 1. K 线口径

图上展示的是原始 K 线数据。

分型和笔的计算基于处理包含关系后的标准 K 线。

每根标准 K 线会记录：

```text
time              标准 K 线日期，永远向右归属
high              标准 K 线高点
low               标准 K 线低点
original_index    右侧原始 K 线序号，用于图上定位
source_times      由哪些原始 K 线合并而来
high_source_time  标准 K 线高点来自哪一天
low_source_time   标准 K 线低点来自哪一天
```

“永远向右合并”的含义：

```text
两根或多根 K 线发生包含合并后，合并出的标准 K 线日期和序号使用最右侧原始 K 线。
价格高低点可以来自被合并的任意一根原始 K 线。
```

因此可能出现：

```text
标准 K 线日期是 2026-06-25
标准 K 线高点来自 2026-06-24
图上 hover 2026-06-25 原始 K 线时，高点不同于标准 K 线高点
```

这是包含关系合并后的正常结果。

## 2. 包含关系

两根 K 线存在包含关系的条件：

```text
A.high >= B.high 且 A.low <= B.low
或
A.high <= B.high 且 A.low >= B.low
```

如果没有包含关系，右侧 K 线直接作为新的标准 K 线加入序列。

如果存在包含关系，则把上一根标准 K 线 `last` 和当前原始 K 线 `current` 合并，合并后的标准 K 线替换 `last`。

## 3. 合并方向

合并方向由最近两根标准 K 线判断：

```text
如果 last.high > prev.high 且 last.low > prev.low，则为上涨方向
如果 last.high < prev.high 且 last.low < prev.low，则为下跌方向
其他情况默认按上涨方向
```

标准 K 线不足两根时，也默认按上涨方向。

## 4. 包含合并取值

上涨方向合并：

```text
high = max(last.high, current.high)
low  = max(last.low, current.low)
```

下跌方向合并：

```text
high = min(last.high, current.high)
low  = min(last.low, current.low)
```

同时记录 `high_source_time` 和 `low_source_time`，用于解释标准 K 线高低点来源。

## 5. 顶分型

在标准 K 线序列中，连续三根标准 K 线：

```text
left, middle, right
```

如果中间标准 K 线同时满足：

```text
middle.high > left.high
middle.high > right.high
middle.low  > left.low
middle.low  > right.low
```

则 `middle` 是顶分型。

顶分型价格：

```text
price = middle.high
```

顶分型还会记录三元素范围：

```text
elementHigh = max(left.high, middle.high, right.high)
elementLow  = min(left.low, middle.low, right.low)
```

顶分型解释会展示：

```text
由哪三根标准 K 线形成
每根标准 K 线由哪些原始 K 线合并而来
标准 K 线高低点及来源日期
为什么 middle 高点、低点均高于左右两侧
三元素最高和最低
```

## 6. 底分型

在标准 K 线序列中，连续三根标准 K 线：

```text
left, middle, right
```

如果中间标准 K 线同时满足：

```text
middle.low  < left.low
middle.low  < right.low
middle.high < left.high
middle.high < right.high
```

则 `middle` 是底分型。

底分型价格：

```text
price = middle.low
```

底分型还会记录三元素范围：

```text
elementHigh = max(left.high, middle.high, right.high)
elementLow  = min(left.low, middle.low, right.low)
```

底分型解释会展示：

```text
由哪三根标准 K 线形成
每根标准 K 线由哪些原始 K 线合并而来
标准 K 线高低点及来源日期
为什么 middle 低点、高点均低于左右两侧
三元素最高和最低
```

## 7. 连续同类分型过滤

如果连续出现同性质分型，则只保留更极端的那个。

连续顶分型：

```text
如果后一个顶分型 price > 前一个顶分型 price，则替换为后一个。
否则保留前一个。
```

连续底分型：

```text
如果后一个底分型 price < 前一个底分型 price，则替换为后一个。
否则保留前一个。
```

价格相等时保留前一个。

构笔中已有末笔时，延伸同类端点必须重新满足末笔起点与新终点的价格范围；成立后同时更新末笔终点时间、价格、原始序号和解释。不能只移动下一笔起点，造成两笔断开。

这套规则在两个阶段生效：

```text
filter_fractals 阶段：对识别出的分型序列做过滤
build_bis 阶段：构笔过程中如果再次遇到同类分型，也按相同口径更新候选端点
```

## 8. 成笔基础规则

一笔由满足间隔与价格范围的有效端点组成，必须顶底交替。反向候选不满足规则时跳过；后续同类更极端分型可延伸当前末笔，因此这里的“相邻”指构笔后接受的端点，不保证是检测序列中紧邻的两个分型。这是项目约定，不能当作对所有缠论流派的统一定义。

```text
底分型 -> 顶分型 = 向上笔
顶分型 -> 底分型 = 向下笔
```

同类分型之间不会直接成笔。

## 9. 成笔最小间隔

成笔最小间隔使用合并后的标准 K 线序号计算，不使用原始 K 线序号。

```text
gap = right.mergedIndex - left.mergedIndex
```

兼容方案默认参数：

```text
minKlineGap = 1
```

独立分型方案生效间隔为 `max(minKlineGap, 4)`：两个三元素分型不共用标准 K 线，中间至少保留一根。间隔指中心序号差，不是两分型之间的空白根数。详见第 26 节。

如果：

```text
gap < minKlineGap
```

则不能成笔。

前端输入框“标准K线最小间隔”传入的是这个参数。

## 10. 成笔价格范围规则

一笔内的顶分型和底分型必须满足严格价格关系。

设：

```text
top.price                 顶分型最高点
top.elementLow            顶分型三元素最低点
bottom.price              底分型最低点
bottom.elementHigh        底分型三元素最高点
```

必须同时满足：

```text
top.price > bottom.elementHigh
bottom.price < top.elementLow
```

业务含义：

```text
顶分型最高点必须严格高于底分型三元素最高点
底分型最低点必须严格低于顶分型三元素最低点
```

边界相等不允许成笔。

## 11. 最后一笔状态

如果已经生成了至少一笔，最后一笔会标记为未确认：

```text
confirmed = false
```

原因是后续新增 K 线可能改变最后的分型或笔。

其他笔：

```text
confirmed = true
```


## 13. 线段输入

线段识别以当前有效笔序列为输入。

线段必须满足：

```text
至少由连续三笔组成
第一笔和第三笔方向相同
前三笔存在严格有效的公共价格重叠区间
```

前三笔公共重叠区间：

```text
overlapLow  = max(三笔各自的最低价格)
overlapHigh = min(三笔各自的最高价格)
```

必须满足：

```text
overlapLow < overlapHigh
```

仅在一个价格点相等不视为有效重叠。

## 14. 线段方向与特征序列

线段方向由起始笔方向确定：

```text
从向上笔开始：向上线段
从向下笔开始：向下线段
```

特征序列由与线段方向相反的笔组成：

```text
向上线段：取其中的向下笔
向下线段：取其中的向上笔
```

特征序列元素记录：

```text
high / low
来源笔序号
包含合并前的全部来源笔
高点来源笔
低点来源笔
与前一元素是否存在缺口
```

## 15. 特征序列包含处理

相邻特征序列元素存在包含关系时，按当前线段方向合并。

向上线段的特征序列：

```text
high = max(left.high, right.high)
low  = max(left.low, right.low)
```

向下线段的特征序列：

```text
high = min(left.high, right.high)
low  = min(left.low, right.low)
```

合并后的元素保留全部来源笔，并分别记录高点、低点来自哪一笔。

特征序列必须按笔的时间顺序增量处理。每加入一根新的特征笔，就更新当前标准特征序列并检查分型；一旦最早的合法线段终点完成确认，立即锁定该终点。终点之后的未来特征元素不得再反向合并并改写已经确认的历史线段。

## 16. 特征序列分型

向上线段寻找标准特征序列顶分型：

```text
middle.high > left.high
middle.high > right.high
middle.low  > left.low
middle.low  > right.low
```

线段候选终点取中间特征元素最高点的来源笔起点。

向下线段寻找标准特征序列底分型：

```text
middle.low  < left.low
middle.low  < right.low
middle.high < left.high
middle.high < right.high
```

线段候选终点取中间特征元素最低点的来源笔起点。

用于确认分型的三个特征元素，其全部来源笔必须已经确认。

## 17. 线段破坏与确认

确认旧线段结束前，候选终点之后必须已经存在反向线段的前三笔重叠结构。这保证线段由反向线段破坏，而不是由单独一笔直接破坏。

### 无缺口

向上线段的特征序列向上缺口：

```text
middle.low > left.high
```

向下线段的特征序列向下缺口：

```text
middle.high < left.low
```

不满足对应缺口条件时属于无缺口。

如果特征序列分型第一、第二元素之间无缺口，并且反向线段前三笔结构成立，则原线段在特征分型极值处确认结束：

```text
breakType = NO_GAP
confirmed = true
```

### 有缺口

如果特征序列分型第一、第二元素之间存在缺口，不能立即确认原线段结束。

从候选终点开始构造反向线段的标准特征序列：

```text
原向上线段：反向向下候选段需要形成特征序列底分型
原向下线段：反向向上候选段需要形成特征序列顶分型
```

按时间扫描遇到最早合法有缺口候选但二次确认尚未成立时，必须等待该候选，不能越过它确认后面的无缺口终点。否则新增笔可能让较早候选完成确认并改写已确认历史。

反向特征序列形成对应分型，且相关来源笔均已确认后，原线段完成二次确认：

```text
breakType = GAP_CONFIRMED
confirmed = true
```

## 18. 未确认线段

如果已经满足前三笔重叠，但尚未出现满足严格特征序列规则的破坏，则生成当前候选线段：

```text
breakType = UNCONFIRMED
confirmed = false
```

候选向上线段终点取剩余同向笔终点中的最高点。

候选向下线段终点取剩余同向笔终点中的最低点。

后续新增的笔可能延伸候选线段，或确认新的反向线段。

## 20. 线段级中枢

当前中枢按线段级别识别，输入只使用已确认线段。

初始中枢至少由连续三条已确认线段构成。设每条线段的价格区间为：

```text
segmentLow  = min(startPrice, endPrice)
segmentHigh = max(startPrice, endPrice)
```

前三条线段的共同重叠区间为：

```text
ZD = max(三条线段的 segmentLow)
ZG = min(三条线段的 segmentHigh)
```

必须严格满足：

```text
ZD < ZG
```

如果 `ZD == ZG`，只有价格点接触，不构成中枢。

## 21. 中枢延伸与离开

初始三段形成中枢后，`ZD` 和 `ZG` 锁定，后续延伸不会改写核心区间。

后续已确认线段满足以下条件时纳入当前中枢：

```text
segmentLow < ZG
且
segmentHigh > ZD
```

这表示该线段与中枢核心区间存在严格价格重叠。

整个中枢全部组成线段的价格范围记录为：

```text
DD = min(全部组成线段的 segmentLow)
GG = max(全部组成线段的 segmentHigh)
```

第一条不再与核心区间重叠的已确认线段用于判断离开方向，但不计入当前中枢：

```text
segmentLow >= ZG   -> LEFT_UP，向上离开
segmentHigh <= ZD  -> LEFT_DOWN，向下离开
```

如果尚无已确认线段完全离开，则：

```text
status = EXTENDING
```

未确认线段不能建立、延伸或确认中枢离开。

## 22. 中枢字段和解释

中枢字段包括：

```text
startTime / endTime
zd / zg
dd / gg
startSegmentIndex / endSegmentIndex
segmentCount
status

```

前端中枢区域只绘制核心区间 `[ZD, ZG]`，横向覆盖第一条至最后一条组成线段。延伸中的中枢使用虚线边框，已向上或向下离开的中枢使用实线边框。

点击中枢区域时展示：

```text
起止时间
ZD / ZG / DD / GG
组成线段数量与序号
延伸或离开状态
完整判定依据
```

## 23. 中枢扫描边界

识别器从左到右扫描线段。找到一个中枢后，当前中枢延伸到最后一条仍与核心区间严格重叠的已确认线段；下一次扫描从该中枢之后开始。

因此当前实现不会把同一条线段重复归入两个中枢。

## 24. 数据周期

当前支持：

```text
daily     日 K
weekly    周 K
monthly   月 K
hour4     4 小时 K
minute60  60 分钟 K
minute30  30 分钟 K
minute1   1 分钟 K
```

不同周期分别抓取、存储、计算分型、笔、线段和中枢。

日 K、周 K、月 K 使用日期作为时间字段。

4h、60min、30min、1min 使用完整日期时间作为时间字段，分型、笔、线段、中枢和解释信息均保留到秒，不能只按日期定位。

A 股日内周期使用腾讯分钟 K 线数据：

```text
1min   直接使用 m1
30min  直接使用 m30
60min  直接使用 m60
4h     使用同一交易日内的 60min K 线聚合
```

4h 聚合口径：

```text
open   = 当日第一根 60min K 线开盘价
high   = 当日全部 60min K 线最高价
low    = 当日全部 60min K 线最低价
close  = 当日最后一根 60min K 线收盘价
volume = 当日全部 60min K 线成交量之和
time   = 当日最后一根 60min K 线时间
```

A 股完整交易日共 4 个交易小时，因此当前 `hour4` 实际对应一个 A 股交易日的四小时交易时段。交易日尚未结束时，最后一根 4h K 线属于当日未完成 K 线。

同一交易日重复同步 4h 数据时按交易日覆盖，收盘后的完整 4h K 线会替换盘中的未完成 K 线，不保留同日重复记录。

前端切换日内周期时，4h 默认查询近 120 个自然日，60min、30min、1min 默认查询近 10 个自然日。免费行情源的实际历史长度有限：

```text
4h 由最多约 320 根 60min K 线聚合，通常可得到约 70 至 80 根
1min 最多返回最近约 320 根 K 线
30min / 60min 在近 10 个自然日范围内按实际可得数据返回
```

系统不补造行情源未返回的历史分钟数据。

## 28. 可追溯结果与一致性

每次结果记录 `analysis`：

- 计算批次 `runId` 与 UTC 时间 `generatedAt`。
- `ruleVersion`、输入设置 `settings`、实际生效 `effectiveMinKlineGap`、原则编号和当时完整 `ruleCatalog`。
- 全量输入根数和范围，以及 `inputHash`、`engineHash`、`ruleHash`、`resultHash`，均为 SHA-256。
- `engineHash` 根据算法、schema、存储及服务代码内容计算，未提交的代码改动也会触发失效。

API 使用 `{SYMBOL}_{PERIOD}_analysis.json` 的单个原子快照；结构与研究指标 CSV 是可读导出，不能据其单独判断是否属于同一批。快照发布前保留在 `analyzed/runs/{SYMBOL}_{PERIOD}/{runId}.json`，包含输入、输出和规则目录。发布失败的存档可作为计算尝试记录，当前快照才表示已发布结果。存档不自动清理，重要历史应额外备份。

查询时若原始行情、代码或规则指纹变化，按上次保存设置全量重算。没有快照的旧 CSV 无法反推原参数，首次使用兼容默认设置从原行情重建，重新生成溯源，不能声称复原了未知旧参数。快照损坏或校验失败返回 409，不猜测设置。

同步省略参数时继承当前方案与间隔；显式参数应用新设置。空行情响应不会清除已有结果。重算的日期仅用于后续展示，始终用完整本地历史计算，避免截断上下文污染持久结果。范围之外相交的笔/段/中枢仍保留完整解释。范围响应的索引、`sourceCount` 和 `resultHash` 都对应全量快照，不是裁剪数组的局部编号和校验值。

分析入口拒绝非法 OHLC、NaN/Infinity、负成交量、重复/乱序时间；请求拒绝未知方案、参数拼写错误、非整数间隔、1至20以外间隔和倒置日期。使用完全相同的行情和设置，几何结果应相同；批次 ID 与计算时间不同属于正常现象。

历史稳定性限定在**已有输入行情不变、规则不变，仅追加未来数据**的前提下。末笔、候选段和延伸中枢允许变化，已确认笔/段的几何终点不得因后来候选确认而倒退改写。历史行情修订或规则切换可改变历史，这是新批次，需通过快照比较说明差异。

当前写入锁只保护单进程内同股票同周期操作，CSV MVP 必须以单 worker 运行；这不提供多进程/多机器事务或断电持久性保证。数据源复权选择尚未统一（腾讯日/周/月优先前复权，Yahoo 路径未自动复权，日内源另有口径），指纹证明输入一致，不能证明市场数据正确。


## 29. 研究分析与买卖点（v3.0.0）

以下是我选择的**可执行工程口径**，供用户修改与对照，不宣称是所有流派统一的缠论定义。参考[第24课背驰与MACD辅助](https://chanlun108.cn/chanzhongshuochan108ke/24.html)及第20课中枢/三类点；以价格结构为先，MACD为辅助。没有信号时返回空数组，绝不造点。

| 原则 | 采用的口径 | 性质 |
| --- | --- | --- |
| F04 | 成笔仅消费右标准K已冻结的原始分型，不预先删除同类历史依据 | 确认稳定性工程约束 |
| F03 | 顶：右原始收盘严格跌破左元素低点为强；否则右元素低点严格跌破左元素低点为中；否则弱。底镜像：右收盘/右高点严格突破左高点 | 项目三元素反向突破分级，非概率 |
| M01 | 收盘EMA，DIF=快EMA−慢EMA，DEA=DIF的EMA，柱=2×(DIF−DEA)；同向柱面积比较 | MACD辅助，不是背驰证明 |
| T01 | 同层三确认单元严格重叠；离开加确认回试后剔除连接离开单元；包络严格分离判方向趋势 | 可切换笔/线段的研究中枢 |
| V01 | 同向新极值且柱面积比不超过阈值；中枢内DIF/DEA回拉零轴；区分局部、盘整及趋势背景 | 项目量化背驰候选口径 |
| P01 | 两同向分离中枢的趋势背驰为一类；确认一类后首次反向单元加首次不破极值回试为二类 | 同层研究点，买卖镜像 |
| P02 | 已形成中枢，离开后首个反向回试严格不回核心才有三类点 | 只突破不能产生三类点 |
| P04 | 基础笔级观察与L0/L1独立标注，复合快照保存同批证据 | 显示层级边界 |
| P03 | 保存端点和最早可观察时间，依赖未完成时为候选；默认图上用观察时间标点 | 防止端点回填冒充当时已知 |

### 参数与动能

`signalLevel=bi` 默认笔级，可选 `segment` 线段级；指结构单位，不等于K线周期或者已经证明的递归走势级别。默认 `macdFast=12/macdSlow=26/macdSignal=9`，快周期必须小于慢周期。EMA初值为首根收盘，DEA初值0，索引达到 `3*macdSlow-1` 才预热完成。

单位动能统计原始K线 `(起点,终点]`，避免共享端点双计。上行只累计正柱，下行只累计负柱绝对值，同时记录峰值、成交量、端点幅度百分比和每根平均幅度。任一统计柱未预热则不判背驰。与前同向单位比较：面积比≤`divergenceRatio`（默认0.8）为弱；大于其倒数为强；其余中；前面积接近0或无有效预热为不可比较。幅度和速度只是描述，并不加入买卖点过滤。

### 信号中枢与趋势

`centralZones` 保留原线段重叠口径，`signalZones` 独立按所选同层单位计算并标注；两者不可混用。至少三连续已确认单位严格交集：ZD=max低，ZG=min高，ZD<ZG。初始核心固定，延伸包络覆盖成员。

从核心相交向外的离开单元，其首个反向回试确认且完整区间严格位于核心外，才关闭旧信号中枢：离开连接单元不计入旧包络，下一轮扫描从回试单元开始。否则交集单位继续延伸。保存 `formedAt`、`closedAt` 和 `departureUnitIndex`，关闭前末尾成员及包络可调整；核心不变。包络分离要求后DD>前GG为向上，后GG<前DD为向下；核心严格相交为扩展关系，其余包络接触/重叠为扩张候选，**没有执行递归级别升级**。最近两枢决定当前趋势摘要；仅一个枢或未严格分离为盘整，有效枢不足为结构不足。

### 背驰及三类点

对每个单位C只使用它之前的已形成前缀中枢，A取最近中枢之前最后一个同向单位；无有效进入单元则与前同向单位比较，仅记局部衰减。C端点须严格超过A同向极值、A面积>1e-12、C/A≤阈值。中枢内至少一根预热K线满足 `max(abs(DIF),abs(DEA))≤zeroAxisTolerance*abs(close)`（默认0.01）为回拉零轴；未满足降为局部衰减。

有一个有效中枢背景为盘整背驰；有两个同方向严格分离包络、A不早于前枢末成员、C端点还超出后枢包络才为趋势背驰。一类点只接受趋势背驰：下行B1，上行S1；盘整或局部衰减不硬转为一类点。

二类点必须有已确认B1/S1，取随后第一个反向单位和再随后同向回试：B2低点严格高于B1，S2高点严格低于S1；相等不成立，不跳过失败首次回试去寻找后续。引用parentId与一类点极值失效参考。

这是当前实现的二类点子集，不是原文全部二类点的必要条件。第53课讨论的没有同级别一类点、小级别转大级别的二类点分支尚未实现。趋势/盘整背驰的量化过滤也可能因缺预热历史而无输出；不能把无模型点解释为市场不存在对应理论买卖点。真实通富样本逐笔核查见 `docs/research/tongfu-signal-coverage-20260930.md`。

三类点要求中枢已形成及离开单位已确认：上离开终点>ZG，紧邻反向回试完整区间最低>ZG为B3；下离开终点<ZD，紧邻回试最高<ZD为S3；触边不成立。每枢每方向只记录首个有效离开/回试组合，参考失效价为ZG/ZD。三类点可独立于一/二类点存在。

### 因果时间与可追溯性

笔在下一笔首次成立时锁定，以原始K线前缀回放首次确认同一笔几何的时间为准；线段依赖特征序列及缺口二次确认所需来源笔的确认时间。研究单位必须同时具有结构确认和确认时间才算完成。点的 `observedAt` 取全部依赖确认时间最大值，含中枢关闭和父点；`time` 为结构端点。末笔/末段及未完成回试只产生候选，可延伸或消失；默认按观察时间标点，切换结构端点明确为事后视图。

“模型确认”只表示本规则的结构条件满足，不表示盈利保证，也不代表当前仍有效。失效参考价不是自动止损单。已有输入/参数不变、仅追加未来数据时，确认点的ID、价格、类型及观察时间应稳定；规则或行情修订必须新批次比较。全量快照包含指标、研究枢、关系、背驰、买卖点及理由；旧v2快照先校验原始载荷，再继承旧笔设置迁移重算，新增参数采用公开默认值。


## 30. 从最低结构种子向上递归（v4.0.0）

用户确认从小结构向大结构推算，本次新增独立递归分析链。v3单周期算法保留为“原单周期模型对照”，不静默改变它的几何。前端首次默认递归、基础5m、最大L4；这是观察输入选择，不是声称5m等于缠论某个固定级别。旧单周期API继续工作。

| 原则 | 采用的口径 | 性质 |
| --- | --- | --- |
| R01 | L0由特征序列线段初始化；父走势有子级中枢后，以反向离开和首次外侧回试确认完成 | 明确的工程完成约定，不是完整原文证明 |
| R02 | 展示周期、基础周期、递归层分离；层只能来自前层，记录组成及确认依赖ID；没有结构就停止 | 结构递归与可追溯性 |
| R03 | 点保存原始端点/观察时间、基础周期和L层；分钟展示必须有覆盖该时刻的周期结束K线，不跨缺失区间；日/周/月仅映射显示，不升级信号级别 | 展示映射与防回填 |

### 最低层与上层构造

L0选用既有特征序列线段作为最低走势**种子**；confirmed和confirmedAt都满足才完成，末线段保留候选。不采用三笔交集作为递归中枢。种子ID追溯到基础笔序号、特征序列、基础分型及完整原始分钟K线。

对任一层L的走势种子/已构造走势，以相邻三连续确认单位的严格范围交集形成同层枢；延伸/离开沿用v3研究枢规则。上层构造按时间从最早子单位扫描，至少一个子级枢才有父走势；后枢包络与前枢严格分离且方向匹配为趋势，否则盘整。L0不是经过证明的严格完成走势类型，上层继承这个初始化边界。

父走势方向取首个子单位。只有反向子单位离开最近子级枢，紧邻的反向于离开单位的回试完整区间仍在枢外，且两单位均已确认，才锁定父走势：父上行要求反向下离开终点<ZD且回试最高<ZD；父下行要求上离开终点>ZG且回试最低>ZG。触边不成立。

几何终点取反向离开之前同方向子单位的最极端终点（同价取早者）；该几何范围内必须已存在子级枢，不能借后面的确认结构补一个枢。childIds记录几何成员，confirmationIds记录终点之后的确认依赖，childZones保存该父走势当时使用的完整中枢上下文。观察时间取全部依赖的最晚时间。下一父走势从终点后的反向子单位开始，保持端点连接。

没有完成证据时，只在确认子级已有枢且方向极值范围足够时输出一个候选父走势；否则停止。候选不能成为更上层中枢的确认成员。每一层输入只能是前一层输出，不能跳层或按钟表比例升级，最大请求层L1至L8，默认L4；实际不足时不生成空壳层。

### 各层买卖点

各层使用本层单位/中枢分别执行V01/P01/P02的公开结构及MACD辅助条件，不等到最大层才产生点。MACD始终由同一基础周期原始收盘计算，父走势动能重新统计自身原始区间 `(start,end]`，不把子单位面积相加而重复计端点。

点包含sourcePeriod、structuralLevel、unitId及本层中枢/背驰/父点ID。不同层ID命名空间隔离，点可指回具体走势，并逐层展开到基础笔。小层卖点不直接确认高层上涨终止；高级别未完成时只能是候选结构。

### 展示、快照与边界

展示行情与基础行情分别从单周期完整已提交快照读入，再把两份输入、原始来源批次、全部层和点保存为**一个复合原子快照**。保存 `analyzed/{symbol}_{display}_hierarchy.json`，全量历史存档在 `analyzed/runs/{symbol}_{display}_hierarchy/`。复合resultHash覆盖基础原始数据、结构和来源元数据；inputHash仍对应展示行情，基础inputHash在hierarchy.baseAnalysis内。代码、输入或基础规则指纹变化自动重建。

复合快照同时保存该展示周期上次基础周期及最大层；查询不带覆盖参数时继承。基础几何/动能设置使用基础快照设置，同步省略参数沿用。同步按钮明确同步基础和展示行情，重算使用完整本地基础历史，日期只裁剪展示。

日K标记映射到原观察时间对应交易日，周/月映射到该时间的日历周/月；原time/observedAt保持完整分钟值。1m/5m/30m/60m日内显示仅映射到同日第一个结束时间不早于观察时间、且二者时间差严格小于该周期长度的K线。若上午数据缺失，不能把上午点挪到下午首根K线；无法映射的点保留原始时间供明细查看，图上不补点。4h交易日聚合及日/周/月映射口径不变。同日多个点在点击解释中分别显示。不能把映射后的日K点叫日线走势级别点，不能把当日收盘当作盘中已知信息。

新增真实A股5m源，默认30日请求窗口，5m源为新浪最多1023根，其他分钟源仍为腾讯最多320根。历史不足、未形成高层和预热不足明确提示；基础为空不回退日K。日K展示时以真实日K交易日期核对基础首尾之间缺失交易日，缺日则停止递归，避免把不连续缓存连接；交易所假期不当作缺口。非日K展示目前只提示未完成逐日完整性核对。同日漏分钟尚未建立完整会话校验，跨周期复权口径也未统一，不提供全年完整性保证。

本次实现的是可执行、逐层引用、可回放的**工程结构递归**。最低种子及父走势完成约定仍需对照原文进一步验证，不能宣称穷尽所有走势分解、级别扩张或实现完整严格缠论。

## 31. 转折边界包含修复及5m来源（v4.0.1）

依据[缠中说禅第71课](https://chanlun108.cn/chanzhongshuochan108ke/71.html)对假设转折边界的说明：边界前最后特征元素与边界后的第一笔不能直接按同段元素包含合并。旧程序统一合并，实际吞掉了立讯精密9月22日10:50的转折，阻塞了后续全部线段。

S02增加一个明确、有界的确认分支。向上段：转折点是此前段内最高端点，至少已有三笔；边界第一根反向笔的高点严格高于此前最后标准特征元素、高低区间向外包含它，低点严格跌破该元素低点；反向前三笔严格重叠；第三笔或其后的反向笔先突破第一笔终点，且在此之前没有先突破第一笔起点。此前段内笔及截至突破笔的反向序列全部已确认时，确认原段结束于该转折。向下段按高低镜像。确认依赖为首次突破笔，观察时间沿用它的confirmedAt。边界元素分别保留来源，不进行跨边界包含合并；仍记为无缺口破坏，并在reasons说明该分支。

只破坏第一笔、第三笔触及第一笔终点或仍在其范围内、来源笔未确认均不能当下确认。第三笔被包含时继续等待先破终点还是先破起点；先破起点则取消该候选边界，同时等待既有特征序列规则，不把所有三笔重叠都当作线段完成。该分支与既有分型按观察前缀逐步检查；已有缺口候选优先等待的规则保留。图形变化是接受的缺陷修复，不代表改变中枢/背驰阈值或以每月点数定规则。

5m同步改用新浪原始分钟OHLC，单次请求最多1023根，默认30日日期过滤。volume单位为股，amount沿用原字段；不乘腾讯接口的100倍换算。1m/30m/60m仍使用腾讯320根接口，4h仍由60m聚合。5m请求失败不静默换源拼接、不使用demo。窗口不能倒推出全年分钟历史。来源时间范围与输入指纹仍记录于完整快照。此次立讯精密旧5m缓存全部在新来源覆盖范围内，备份后由新浪记录覆盖，未保留腾讯残片。日K仅作展示底图，分钟价和日K复权口径仍可能不同。

此外，普通分型分支的转折必须是截至该转折的段内方向极值，且上段终点严格高于起点、下段严格低于起点。禁止将之后局部高点错认成更早上段的结束，产生上行线段净下跌。

P03确认时间改为逐根原始K线前缀回放，按首次生成同一已确认笔几何记录时间；后笔候选端点延伸不再推迟此前笔的确认时间。线段沿用依赖笔最早确认时间与此前线段链的确认时间最大值，不能在其起点边界尚未确认前宣称可观察；信号取全部结构依赖的时间最大值。该回放使用相同包含、分型筛选、成笔方案，不修改几何来追求点数；比一次性分析多出回放开销，完整快照缓存复用结果。

递归日K图默认缩放到基础分钟行情覆盖日期并保留右侧标注空间，MACD展示图同步视窗；数据查询日期、全量分析和信号映射时间不变。仍可拖动/缩放查看更早日K背景。

## 32. 首段方向初始化（v4.0.2）

S01初始化除了三笔严格重叠，还要求第三笔沿第一笔方向严格突破第一笔终点：上行third.endPrice > first.endPrice，下行third.endPrice < first.endPrice。等价或未突破都不能直接定向初始化。扫描从左到右，使用第一组符合条件的三笔；此前不足以独立确定方向的片段不补造一条已确认线段。首段当前第三笔可以仍为候选，整段依然未确认；完成确认仍依照S02。

依据第71课对方向未定三笔、先破哪一端的讨论，以及本项目已有段末端必须是方向极值的约束，此处采用明确的冷启动工程口径。历史起点可能落在一条未知线段中，所以不能仅凭三笔重叠，把第一笔方向强加给整段。此规则不是声称原文给出唯一的截断行情初始化算法。

仅改变首次起点选择，不改变普通/边界转折、反向候选三笔、缺口二次确认的条件。反向候选第三笔被包含时仍允许等待后续先突破；不能把冷启动条件一概套在所有反向候选上。既有minKlineGap、MACD和背驰阈值、买卖点条件保持原值。

通富微电首三笔UP→DOWN→UP终点62.57/61.30/62.42，第三笔没有超过第一笔高点；原初始化使75笔压进两个段。正确首组三笔从第1笔（索引1）DOWN开始，第三笔跌破第一笔终点，修复后形成10条确认段与1条候选段，L0两个枢，并由其子结构生成L1。详见决策0005中的同输入比较。

P03前缀回放也覆盖线段：首次出现已确认的同一段几何时，冻结当时featureSequence、confirmationBiIndex、breakType及reasons，时间取该原始K线前缀末端。不能只冻结时间却保留后续新增的确认依赖；也不能用全量特征元素后来延长后的源笔索引推迟历史确认。已确认段的几何不因这一修复而改变；时间和证据可能按实际首次可观察时刻修正。

## 33. 可变右支撑不得锁定历史笔（v4.1.0）

F04：末标准K线仍可能被后续包含合并改变，使用它作为右元素的分型尚不能参与成笔。显示分型仍按F02同类极值过滤，可能含当前可变分型；成笔输入使用全部已检测且右元素已冻结的分型，不预先删除同类分型，内部按B02/B03判断反转与同类延伸。冻结判据为right.klineIndex < 最后标准K.originalIndex，即右元素后已出现另一根标准K；仅多一根被包含的原始K不能使右元素冻结。

历史TOP的右元素后来下移，可能使原先满足的笔价范围失效。旧实现提前将这种分型作为确认依据，产生“已确认笔”端点向未来移动。通富9月15日14:50顶的右元素由14:55延长到次日09:35，最低价下移至56.91，旧下笔39曾被错误锁定，后又延伸。新规则等待该右元素冻结，避免回填过早确认。前缀回放采用完全相同的输入筛选；笔/段/信号确认仍需要其全部依赖先已知，不能单独提前日期。

笔级点与L0线段种子点按不同单元计算，不升级笔级观察点的递归层级。当前同样参数下通富有笔级B3：端点9月29日10:10，确认10:30；L0仍无买点，S3端点9月15日10:35，确认次日10:10。立讯L0两S3确认时刻相应校正至9月21日15:00及9月29日13:10。历史4.0.x记录不作为最新输出。

## 34. 笔级观察图层（v4.1.0）

P04：在同份基础K线、实际笔参数和MACD参数上，以BI为单元生成观察中枢、背驰和点，保存在hierarchy.baseTradingPoints/baseSignalZones/baseDivergences；递归layers与根tradingPoints仍仅为L0/L1…结果。观察点structuralLevel=null，sourcePeriod为实际基础周期，unitId=bi:索引。所有确认条件、价格严格边界及实际观察时间沿用P01/P02/P03，不为了出现买点改变阈值。
